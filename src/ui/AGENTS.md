# `src/ui/` — `gpaste-ui` (GTK4 + libadwaita)

The main graphical history browser, launched via `gpaste-client ui`: the history list, item actions, search and the history panel. Its source files are commented where the reasons live; this file is the map, and the conventions that span several of them.

## Widgets

- `AdwApplicationWindow` (through `G_PASTE_GTK_INIT_APPLICATION`, which uses `AdwApplication`), under an `AdwToastOverlay` (every failed call reports through it) over a `GtkBox` of an `AdwBanner` (the daemon connection, see below) and an `AdwNavigationSplitView` (history panel + history list).
- One `AdwToolbarView` and `AdwHeaderBar` per `AdwNavigationPage` — there is no window-level toolbar view, every bar belonging to a page — which is what gives a collapsed window its back button. The sidebar's bar is bare and shows its page title; the content's is `g_paste_ui_header_new ()` with an `AdwWindowTitle` (the history name as subtitle), the search bar as a second top bar and the merge `GtkActionBar` at the bottom.
- An `AdwBreakpoint` (`adw_application_window_add_breakpoint()`) collapses the split view below `G_PASTE_UI_WINDOW_COLLAPSE_WIDTH` (in px and in sp, whichever is wider: it follows the text scale up, not down), and `on_history_changed` shows the content page when collapsed, so picking a history navigates to it; setup sets `show-content` too, and `on_split_view_uncollapsed()` sets it again each time the panes go side by side, so a window opened or narrowed to collapse shows the history — never on collapsing, which would move the focus off the list. The minimum size is set in `g_paste_ui_window_init()`, whose comment says why it is not the HIG's; both widths are sized for the widest window buttons (KDE's icon, minimize, maximize and close), and `/ui/daemon-presence/minimum-width`, `collapse-width` and `resize` hold the window to them.
- `AdwStatusPage` for an empty history or a search with no results; `AdwSidebar`/`AdwSidebarSection`/`AdwSidebarItem` for the histories; `AdwShortcutsDialog`/`AdwShortcutsSection`/`AdwShortcutsItem` for the shortcuts; `AdwAboutDialog`.

**Subclassing**: GTK4 made many widget classes final; libadwaita keeps its own derivable. Internal widgets subclass `GtkBox` (`GPasteUiPanel`, `GPasteUiHistory`, `GPasteUiItem`), `AdwApplicationWindow` (`GPasteUiWindow`) and `AdwSidebarItem` (`GPasteUiPanelHistory`, a GObject rather than a widget). `GtkStack` is final — use a `GtkBox` with manual visibility toggling. `AdwHeaderBar` is final too, so the window's header bar is a plain one carrying its buttons as qdata, and its accessors check that the qdata is there, `ADW_IS_HEADER_BAR()` being unable to tell it from anyone else's.

## The window

- **The header bar drives `win.` actions** installed on `GPasteUiWindow`, so a button, a menu item and an accelerator ask for the same thing and the window owns the state. The bar holds what acts on the history — New at the start; Search, Pinned and Select at the end — and one `open-menu-symbolic` `GtkMenuButton` for the application: Track Clipboard Changes (a stateful boolean, rendered as a check), Restart Daemon, Preferences, Keyboard Shortcuts, About GPaste.
- **The tracking check follows the daemon**: activating it asks (`SetActive`, confirming on the way down) and sets nothing, and the client's `tracking` signal is what moves it. A widget of its own with a confirmation hung off a click gesture would let the keyboard bypass both the confirmation and the call.
- **New is an `AdwSplitButton`**: clicking adds a text item, and the arrow's menu names that beside New Password — a primary action with a few related alternatives, the HIG's case for a split button, where two buttons would give a rare action equal billing and a menu button would cost the common case a click.
- **Icon-only buttons set both a tooltip and `GTK_ACCESSIBLE_PROPERTY_LABEL`**: a tooltip becomes the accessible *description*, and an icon gives no name.
- **Failures are reported, not discarded**: a failed call the user set off says so in a toast (`g_paste_gtk_util_toast`, which finds the overlay from any widget) and a `g_warning`. Pair `g_paste_ui_report_void_cb` with `g_paste_ui_report_void (origin, finish, message)`, or the `_string` pair for a `_finish ()` answering a uuid (which the UI ignores: the item arrives as an `update`); `origin` is any widget in the window, and the message a translated literal kept by pointer. `g_paste_ui_panel_history_activate()` is handed a widget, an `AdwSidebarItem` having none to find a window from.
- **Window state is left to GTK**: no geometry key. `GtkApplication` saves and restores it itself, and `init` sets `gtk_window_set_default_size (800, 600)` (and the minimum above) as the fallback. `gtk_application_save()`, which let GPaste save right after a resize settled, was added to GTK (22e45968e2) and made private again (eabaa008d5) before 4.24. Should it come back, restore the coalescing of per-frame resize notifications, and apply the default size *before* connecting any `notify::default-width`/`-height`/`maximized`/`fullscreened` handler, or every launch saves the hardcoded default over the geometry about to be restored (the window being presented only from the async client callback).
- **Window shortcuts** go through a bubble-phase `GtkShortcutController`: Ctrl+0-9 activates the item at that index (triggers from `gtk_shortcut_trigger_create_with_aliases()`, which covers `KP_0`-`KP_9`; the index passed as the shortcut's `GVariant` arguments), Escape leaves selection mode or closes (a callback returning `FALSE` propagates, deferring to an open search bar). `question` has no aliases, so `win.show-help-overlay` stays on `gtk_application_set_accels_for_action()`. `add_window_actions()` registers the rest the same way: `Ctrl+F` search, `Ctrl+N` new item, `Ctrl+Shift+N` new password, `Ctrl+,` preferences, `Ctrl+W` on `window.close`. These are the window's own shortcuts, listed in `gpaste-ui-shortcuts-window.c` and deliberately not in `G_PASTE_FOR_EACH_KEYBINDING` (see the root `AGENTS.md`).
- **The shortcuts dialog is a snapshot** (`gpaste-ui-window.c` and `gpaste-ui-shortcuts-window.c` explain each point): closed on `notify::keybindings-enabled` and `rebind`, coalesced on the daemon's 250 ms rebind delay; the weak pointer dropped at the close itself; a request with a close pending retiring what is up (`retire_shortcuts()`) and building a fresh one — raising the stale snapshot would have the pending close shut it 250 ms later, reading as the accelerator dismissing the dialog — which also cancels a close armed for a dialog the user already shut, a `rebind` with nothing up disarming it; the constructor's floating reference sunk into a `g_autoptr` for the present. The master switch being off is said in the title of every section listing global shortcuts, the only place it can go.
- **The daemon connection is a state every part follows**, through `GPasteClient:daemon-presence` (see the libgpaste `AGENTS.md`): the window calls `g_paste_client_follow_daemon (client, TRUE)` once set up — opening it being the user asking for a daemon — and `unfollow_daemon()` in `dispose`. The list and the sidebar each watch the presence themselves: `READY` lists the history and the histories afresh (a returning daemon announces its history, never the set of them nor the updates that filled the old rows, so a listing also drops the rows it no longer names, bar the default and the current history), anything else empties the list — a spinner while `STARTING`, "History Unavailable" when `ABSENT` — since a bound row asks the daemon for its item and that call is what the bus would start one on. For the same reason **`g_paste_ui_history_refresh()` asks nothing while not `READY`**, whichever view is up: a search bar emptying on its way out, a filter toggled and a deferred `app.search` all come through it, so it is the one gate rather than one per widget. The window takes away what acts on a daemon while there is none (`g_paste_ui_window_update_sensitivity()`: the daemon's actions, the sidebar, the list, the search, favourites and merge buttons, leaving selection mode — its picks name the old list's rows — but keeping the search open with its text, which the list asks again once `READY`, and which Escape closes while there is no daemon, the entry having no focus to do it), keeping the preferences, the shortcuts and About -- the focus taken off the sidebar first when it is there (`g_paste_ui_window_release_focus()`), since GTK drops an insensitive widget's focus without telling it and the "Switch or Create" entry would be left believing it has it, as `on_selection_changed()` does for the Merge popover's entry before its button goes insensitive; the search bar captures keys only while `READY` and out of selection mode (`g_paste_ui_window_update_key_capture()`), and a list that had the focus when the daemon went gets it back once it shows rows again, unless the user put the focus elsewhere meanwhile (`refocus` in `GPasteUiHistory`, noted before hiding the list takes the focus off it).
- **A background read failing only because the daemon left** (`g_paste_client_is_daemon_gone_error()`) — the sidebar's listing, the list's size, search and pinned reads, a row's image preview — is not reported, the presence saying what comes next; what the user asked for (activating an item, resolving a selection) still is. A row's image preview says nothing the user sees, toast or warning, whatever failed — it is read again on every binding — and leaves a debug line. A daemon taking the name over from another is a presence edge like any other (see the libgpaste `AGENTS.md`): the sidebar keeps its rows, but every one bar the default stays disabled until a listing of the daemon now there names it (`g_paste_ui_panel_set_rows_enabled()`), a click on one it lacks creating that history there, and the listing prunes the rest; a context menu left up on a row so disabled acts on nothing (`g_paste_ui_panel_get_menu_history()`); the sidebar lists only while `READY`, as the list does. If the size read fails with no rows to preserve, the list shows "Could Not Load History" with Retry; repeated failures return to that page. A page waiting for rows keeps the focus the list is owed (only the pages that answer, through `g_paste_ui_history_show_answer()` — "No Items", "No Results" and "No Pinned Items" — give it up), and a successful retry moves focus from the hidden status page to the rows, leaving focus elsewhere in the window alone.
- **The banner reads the state through `g_paste_ui_window_update_banner()`**, never from the path that moved it: hidden when `READY`, "Connecting to GPaste…" with no button while `STARTING` or while `g_paste_client_new()` is still out (`connecting`), and "Couldn’t connect to GPaste" with **Retry** when `ABSENT` — which the client reports once a gone daemon's name has had no owner for a grace second, while it goes on waiting for one to reappear. Retry is `g_paste_client_retry_daemon()`, or, when building the proxy itself failed, a new `g_paste_client_new()`, whose `on_client_ready()` then runs `g_paste_ui_window_setup()` into a window already presented — which is what `initialized`, the window having been presented and its deferred actions run, keeps straight. Hidden, the banner keeps its words, so it slides away still saying them.
- **A daemon older than the window gets a toast offering to restart it** (`g_paste_ui_window_update_version_toast()`, through the `restart-daemon` action), checked each time the presence becomes `READY` or the proxy learns the daemon's owner (`g_paste_ui_window_compare_versions()` compares numeric runs by value, places named prereleases before numbered minors — among themselves alphabetically, the order `meson.build` ranks them in — and reads a bare major as its `.0`). Restart, the toast and the menu's alike, is offered only where it could help (`g_paste_ui_window_restart_can_help()`): never for the experimental in-shell daemon, whose `Reexecute` restarts nothing — told apart by its name sharing its owner with the Shell's — and not until both owners are known, the Shell's watch having answered once and the proxy having learnt the daemon's, an unknown owner being no evidence of either. The toast times out as any toast does — a standing one would hold back those queued behind it — and is dismissed early when it could no longer help.
- **The initial focus is the history list's**, taken from the list view's `map` by a handler that disconnects itself. Left to GTK it lands on the sidebar's "Switch to history" `AdwEntryRow`, which then swallows what the user types, since the search bar captures keys in the *bubble* phase. An empty history on open leaves the focus in the entry.

## Dialogs

`gpaste-gtk4/gpaste-gtk-util.c` holds the dialogs, shared with the daemon's prompts:

- `g_paste_gtk_util_confirm_dialog()` takes a **heading** (the question — never the application's name and version), a body (what confirming does), the confirm label and an `AdwResponseAppearance`: destructive only for what is actually lost, so restarting the daemon and pausing the clipboard are not.
- `g_paste_gtk_util_form_dialog()` is every composer's shell: an `AdwDialog` with an `AdwHeaderBar` offering cancel and confirm (not an alert with a form in its extra child) around the caller's content, handing back the confirm button for the caller to keep insensitive while the form is incomplete and again once pressed, `adw_dialog_close()` being asynchronous. `g_paste_gtk_util_text_dialog()` is that shell around a text view — New Item and Edit — answering what was written (`NULL` when cancelled) exactly once, however it or its window goes, and never from finalize, which a reference held on the dialog would put off. That is what lets Edit Item and New Item hand their whole state over to the callback and hold their window weakly (`GPasteGtkTextDialogData`). Its parent has to be one `g_paste_gtk_util_can_host_dialog()` accepts, a resizable Adwaita window, the only kind libadwaita hosts a dialog in: anything else is refused, and still answered as a cancellation (`g_paste_gtk_util_text_dialog()` says why). Edit Item and New Item check their window against it on the way in, Edit Item's dialog only coming after a read. **A `GtkTextView` lays a line out again whenever that line changes**, so what an edit costs is the length of its line and not the size of the text: many lines are free at any size, while one line of fifty thousand characters is about fifty milliseconds a keystroke and one of three hundred thousand is half a second, in every wrap mode. `MAX_COMPOSABLE_LINE` is where the composer stops: it refuses to open over a longer line (answering as a cancellation, with a toast) and refuses an insertion that would make one, so neither opening a huge item nor pasting into the view can freeze the window.
- `gpaste-ui-password-dialog.c` is the shell around an `AdwPreferencesPage` of boxed-list rows: a name and a timeout, plus a password and its strength when composing a new one. While its call is pending the fields and confirm are insensitive but Cancel is not; a failure keeps the entries and reports above them, a name conflict asks for another name, and the reply holds the dialog weakly and always finishes the call. **Editing reads the password's name and timeout back first**, both on one `GCancellable` the root window cancels when it is destroyed. The edit holds that window through a `GWeakRef`, since retaining it would delay GTK's `destroy` signal until the reads released it. `unrealize` also cancels when another operation retains a closed, previously shown window; merely hiding it leaves the edit live: a reply already on its way still lands, so that cancellable -- not the window's visibility -- is what says there is no dialog to put up and nothing to report a failure to. `gpaste-ui-edit-item.c` reads a text item back for Edit Item the same way, on a cancellable of its own and with the window held weakly.
- **`g_paste_gtk_util_password_strength_row_new()`/`_rate()`** are shared so the passphrase prompt and the graphical tool cannot rate a string two ways. Its nullable `unavailable` text defaults to the row's own wording, a build unable to rate being a fact about the build rather than the form — passed only to say it differently (the prompt says "passphrase") — and a build without libpwquality gets an insensitive row saying so. The meter is qdata, `AdwActionRow` being final. `_rate()` keeps the *entry*, never a copy of its text, and rates at most once per `G_PASTE_UTIL_STRENGTH_RATING_DELAY` (200 ms), rate-limited rather than restarted per keystroke; the waiting rating and the meter are dropped on `::destroy`. The extension's prompt rates on the same delay, read off the typelib as `G_PASTE_PROMPT_STRENGTH_RATING_DELAY` (pinned to the original by a `G_STATIC_ASSERT`, like `G_PASTE_PROMPT_STRENGTH_MAX`): `prompt.js` arms one timeout, ignores keystrokes while it is pending, and drops it with the dialog.

## Rows

- **Previews** sit in a slot **between the index and the label**, the label being the row's only expanding child and so the one that gives up width when the buttons appear. An image is a `GtkPicture` thumbnail (`images-preview-size`, `images-preview`) whose custom `query-tooltip` (`gtk_tooltip_set_custom`) shows a larger, capped, aspect-preserved preview; the inline thumbnail stays, being glanceable and keyboard- and touch-friendly.
- **Colour swatches** (`gpaste-ui-color-swatch.{c,h}`, whose comment explains the drawing) use that same slot, parsing the item's value, which *is* its colour. They are a `GtkPicture` of a one-pixel `GdkMemoryTexture` with `GTK_CONTENT_FIT_FILL`, Adwaita's `.frame` and `GTK_OVERFLOW_HIDDEN`. CSS cannot colour one widget (per-widget providers have been deprecated since 4.10, which `GDK_VERSION_MAX_ALLOWED` would flag), and a hand-drawn snapshot would have to track the theme's outline colour itself. Their size does not follow `images-preview-size`, so turning image previews off keeps them.
- **Row actions** are `GSimpleAction`s in a group inserted under `item.`: `edit`, `make-password`, `strip-rich-text`, `upload`, `pin` (stateful, so the menu shows a check) and `delete`. **What a row can do follows its kind**, stored as the `GPasteItemKind` it arrived with and reset to `INVALID` on every (re)binding in `_g_paste_ui_item_set_index()`, since the search path writes the new uuid before the item lands. `upload`, `make-password` and `strip-rich-text` want a text item; `edit` a text item or a password, for which it opens the password composer (a password's name and timeout being all that can be written), which is also why `make-password` is offered on text rows alone. Both go through `MakePassword`. `g_paste_ui_item_update_actions()` disables everything for a row with no uuid.
- **Only pin and delete are inline**, flat, revealed on hover by a `GtkEventControllerMotion`; a pinned row always shows its star, as a badge, which is why the star is the row's **last** child. Each is wrapped in a `GtkRevealer` with a horizontal `SLIDE_LEFT` transition of duration 0 (see `gpaste-ui-item.c`), which keeps a button's height measured on every row while reserving no width.
- **Everything is in a `GtkPopoverMenu`** parented to the row with `gtk_widget_set_parent()` (safe in a `GtkBox`, a popover being a `GtkNative` that layout managers skip), opened by a secondary click, a touch long press, or `Menu`/`Shift+F10` — a `GtkShortcutController` on the **list view**, since the focus is on the `GtkListItem` above the row.
- **Row text uses `GtkInscription`**, not `GtkLabel`, being made for list cells. Set `gtk_inscription_set_text_overflow (GTK_INSCRIPTION_OVERFLOW_ELLIPSIZE_END)` explicitly (the default clips); for bold, `pango_parse_markup` into a `PangoAttrList` for `gtk_inscription_set_attributes`, and `gtk_inscription_set_attributes (NULL)` before `set_text` when going back to plain text.
- **A CSS class that toggles is bound to a property** with `adw_bind_property_to_css_class()` (`GPasteGtkShortcutRow:capturing` → `accent`) rather than paired add/remove calls. A class set once stays a plain `gtk_widget_add_css_class`, and a state that is not a property on some object is not a candidate.

## The history panel

`GPasteUiPanel` lists the histories in an `AdwSidebar`, each a `GPasteUiPanelHistory`. The sidebar's `suffix` slot (an `AdwBin`) holds the "Switch or Create" `AdwEntryRow` inside a one-row `boxed-list` `GtkListBox`, an entry row warning anywhere else. The right-click menu (backup, empty, delete) is a `GMenuModel` set on the sidebar, with `GSimpleAction`s on the panel under `panel.`.

- **Only the latest history listing changes the sidebar**: `g_paste_ui_panel_refresh()` gives up the listing out (its `listing` cancellable) before asking again, and the daemon leaving `READY` or the panel's `dispose()` gives it up too, so an earlier reply cannot add or prune rows after a newer one. The listing holds the panel weakly, so a closed window's sidebar goes without waiting for it.

- **A history row reveals a delete button**, in the *item* rows' idiom: flat, in a `SLIDE_LEFT` `GtkRevealer` of duration 0, set as the item's `suffix`. An `AdwSidebarItem` is a `GObject`, so the row it is drawn on — a `GtkListBoxRow`, whichever mode the sidebar is in — is **found** rather than made, from the one widget of it the item holds (`gtk_widget_get_ancestor (revealer, GTK_TYPE_LIST_BOX_ROW)`), on every `map` of that revealer: a sidebar rebuilding its list hands the same suffix to a brand new row. The row is held weakly, it being the thing that holds a reference on the item.
- **What shows it is the row's `state-flags-changed`**, not a motion controller: GTK marks the whole chain from the pointer's target up, so `GTK_STATE_FLAG_PRELIGHT` on the row covers the pointer being over the button itself, and `FOCUS_VISIBLE` gives the keyboard half (not `FOCUSED`, which a click sets too, leaving the button up on the row just picked). The button is not a focus target — `Delete` on the focused row is, through a `GtkShortcutController` added to that same row, so the key only ever fires for the row the focus is on. `BackSpace` is left alone: GNOME has it mean back, not delete.
- **Both ask the panel, through `GPasteUiPanelHistory::delete`**: the confirmation and the call live once in `g_paste_ui_panel_delete_history()`, which the context menu's action reaches too. The row has neither the window a dialog goes over nor a second wording to drift from.

## The history list

- **`GPasteUiHistory` is a `GtkListView` over `GPasteUiHistoryModel`**, a `GListModel` of `GPasteUiHistoryItem`, through a `GtkSignalListItemFactory` (`setup` builds an empty `GPasteUiItem`, `bind` points it at its item and starts the fetch, `unbind` clears it and drops its uuid). A positional row's index *is* its position (`gtk_list_item_get_position()` at bind); a uuid-driven view (search, favourites) carries uuids instead — the model's `by_uuid` mode, through `g_paste_ui_history_model_set_uuids()`. Since only realised rows are bound, an activation may find no widget: a search row's uuid is in the model, and a positional row is one `GetItemAtIndex` away.
- **Every read is cancellable, and every reply asks whether it is still wanted**: `GPasteUiItem` holds a `GCancellable` for the reads filling it (`GetItem`, `GetItemAtIndex`, `GetImage`), cancelled and replaced on every (re)binding and `refresh`, and each step of the fill chain asks `g_paste_ui_item_still_wants()` of the cancellable *its* read went out on, carried in the callback data, before its `_finish()` — covering a cleared `client` too, since `dispose` cancels and drops it. **The list has one as well** (`self->display`): a refresh (`GetHistorySize`) and a search (`Search`/`GetFavourites`) list the same rows, so allocating a listing's callback data (`display_callback_data_new()`) cancels the one before it. A refresh with no history name to report cancels without a successor.
- **Model updates** map to `g_list_model_items_changed()`: the tail on a resize (`set_size`), one row on an in-place replace (`item_replaced`), and on a refresh the rows whose contents moved (`invalidate`), which **replaces the `GPasteUiHistoryItem`s** as well — see `gpaste-ui-history-model.c`.
- **Lazy loading**: the display count fills the window, with no `max-displayed-history-size`. `self->limit` is what may be on screen and `self->size` (the model's rows) is `MIN (available, limit)`. A batch (`g_paste_ui_history_batch()`) is a viewport's worth, `page_size / row-height + 1`, with `G_PASTE_UI_HISTORY_DEFAULT_BATCH` before allocation, the row height derived as `upper / size` like the extension does. The adjustment's `changed` keeps loading until the content overflows, and `GtkScrolledWindow::edge-reached` (`GTK_POS_BOTTOM`, the idiomatic trigger, there being no libadwaita helper) loads the next batch; `self->loading` stops re-entrant growth. A shrinking history clamps `limit` to `MIN (limit, MAX (batch, available))`. Only the positional view grows: a search lists every match.
- **Merge selection mode** (`GPasteUiHistory`, `GPasteUiHeader`, `GPasteUiWindow`): `g_paste_ui_history_set_selection_mode()` swaps the view's selection model — `GtkMultiSelection` while picking, `GtkNoSelection` otherwise, with `single-click-activate` off while picking — so no row needs treatment of its own. A capture-phase `GtkGestureClick` added in `setup` toggles a row at its current position (plain multi-select would need Ctrl or Shift), and the native highlight is the only cue. **Order is kept as positions** in a `GArray` mirrored from `selection-changed`, since a `GtkBitset` has no order and an unrealised row has no widget to read a uuid off (select-all over a lazily loaded history picks many); `g_paste_ui_history_get_selected_uuids()` resolves them at merge time, with one `GetHistory` for positional rows. The list emits `selection-changed(count)`, and the window updates the header count (`g_paste_ui_header_set_selection_count`) and Merge's sensitivity (two or more). The header shows the mode by hiding what does not belong to picking — Cancel replaces the merge button, the title reads "N selected" — with no style class, libadwaita's `.selection-mode` being for `checkbutton` alone; the rows' own actions hide through `GPasteUiItem:selection-mode`, bound at `setup`. The controls are a bottom `GtkActionBar` (`adw_toolbar_view_add_bottom_bar`); Merge is a `GtkMenuButton` whose popover offers separator presets and a custom one, calling `g_paste_client_merge()` with no decoration and leaving the mode. Escape and Cancel leave it too.
